# 启动提示、关注与自愿赞赏

《翠鸟水庭》1.0.2 收到“页面按钮可能无法点击”的反馈。复测原包时，即使忽略关注和赞赏，也要先关掉启动来信才能移动。赞赏请求挂起后，再次从手记点击也没有反馈。已发布的 1.0.3 保留了来信，玩家可以在两个按钮都可见时，直接用第一下触摸拾取珍藏。其他作品按自己的核心操作验收，例如开始一局、落下一枚棋子或生成一次结果。

## 启动提示与主操作

- 保留作品原有的开始、继续或选关入口。启动关注提示可做成一张非模态小卡，避开主按钮、互动区、摇杆和宿主返回键。提供清楚的略过入口，局内菜单仍可打开关注和赞赏。
- 卡片可在第一次主操作时自动收起，同一次按下、拖动或点击仍须完成原动作。只让卡片自身接收触摸，避免透明全屏层、焦点锁或暂停标记拦截卡片外的输入。点卡片按钮时要吸收该次手势的兼容尾事件，避免误触下方玩法。
- 作品具备开始条件后就启用主操作。后台查询关注关系、赞赏可用性或云档时仍可进入。需要恢复进度时，为读取设置有限等待，并保留本机有效存档和后续冲突选择。

## 从局内打开原生面板

1. 玩家主动点关注或赞赏时，同一次点击先收起作品自己的引导和上层菜单，清除残留的按住状态，恢复可继续操作的页面。可以显示简短状态。原生面板显示期间由客户端接管输入，玩家从面板返回后应能直接继续，即使之前的调用一直没有回调。
2. **关注**。启动和回前台只查询关系。玩家点领取时复查，状态为 `1` 或 `2` 才启用约定的权益，重复确认只生效一次。查到 `0` 且玩家仍在等待这次领取时，才调用一次 `followAuthor`。如果玩家已开始操作或离开本次领取流程，丢弃迟到的弹窗请求。取消、超时、缺少接口或 `-1` 时保留最近一次已确认的关系，允许稍后重试。新查实的 `0` 应停用持续关注权益。[关注权益与存档规则](xhs-platform-apis.md#关注权益的核对与回收)
3. **赞赏**。发布配置、客户端版本和方法都支持时展示独立入口，由这次主动点击调用一次 `rewardAuthor`。成功返回、取消、失败和挂起都不发奖、不改变进度，也不记录已付款。返回后玩家再次主动打开入口可以重试。旧请求不得占住下一次点击，也不得在迟到时重开菜单、改写新状态或覆盖正在玩的页面。[自愿赞赏接口](xhs-platform-apis.md#creator-tips)
4. 同一次桥接调用兼容 Promise 和 `success`/`fail` 回调形式，只处理第一个有效结果。返回 `undefined` 时继续等待回调或走超时分支。回到前台时重新核对关注关系。原生面板只响应新的主动点击。

## 送审前复测

解压**将要提交的 ZIP**，用 `redapp dev --dir <解压目录>` 运行。记录版本、包摘要和测试环境。每部作品都验证冷启动和第一次主操作。其余项目按实际入口和支持的屏幕方向执行。先用平台模拟器实际点击，再用模拟接口复现取消、挂起和乱序。有真机时用同一包的预览码验证原生面板返回。在记录中区分真机、模拟设备和测试替身。

| 场景 | 操作与通过条件 |
| --- | --- |
| 冷启动，忽略引导 | 用新档打开，有提示卡时保留在屏幕上，直接操作作品。第一下就产生可观测结果，如位置改变、收藏加一或结果生成。没有自动弹出关注或赞赏面板。已有存档还能从原进度继续。 |
| 关注与取消 | 未关注时点领取并取消，立即做一次主操作，确认未获权益。再从局内确认关注，验证能力实际生效。已关注时直接识别，连续点领取只打开一次面板，权益不叠加。分别让关系查询和原生确认一直无回调，验证仍可操作并从局内重试。 |
| 赞赏与重试 | 分别模拟正常返回、取消、拒绝和一直不回调。每次回到作品都做一次主操作。旧请求仍挂起时，再次主动点赞赏能产生一次新调用。对比操作前后的道具、权益、货币和付款记录，赞赏带来的变动应为零。 |
| 缺失与迟到 | 缺少接口或版本过低时仍可完成主操作。让查询延迟到玩家开始操作后再返回，再将上一轮的回调放到下一轮之后送达。不得弹出过时面板、抢焦点或重复发放。补测仅回调、仅 Promise 以及两者都返回的宿主。 |
| 小屏与旋转 | 在窄屏上实际点主操作、略过和局内返回。支持旋转时再按竖屏→横屏→竖屏重复。带摇杆的作品检查世界位移、松手停止和镜头方向，同时检查主按钮与系统返回键的触控区域。 |

将失败的动作和实际状态记下来，修复后重打 ZIP，用新包重跑失败路径和主操作。截图、按钮变色或一条提示文字只能辅助定位问题，验收记录应写出玩家实际完成了什么。


## 铁拳入口补充（2026-11-19）

本地旧包故障注入复现：关注桥接无回调时，等待锁挡住回前台核对，局内商店/系统隐藏触发的暂停层留在返回页面；慢查询还能在玩家已出拳后再唤起确认。另一个正常首次进入路径是开局礼物：320×480 下领取/稍后在屏外，旧测试的自动滚动掩盖了问题。以上是本地复现条件，不等同于平台审核根因。

- 将“这次主动领取意图”与“长期确认关系”分开。新的实际操作、离开领取或回前台使旧弹窗意图失效，允许重新点击；旧 Promise 的 finally 只能清理自己的令牌，迟到结果不能覆盖新核对。仍可后台接受有效关系查询，但不能据此自动打开原生面板。
- 入口事件守卫要识别同一触摸的兼容 Mouse 尾事件，不能把它当成玩家的新意图；也不能给下一次真实操作加全局冷却。仅 Promise、仅回调及两者都返回的适配必须单次调用、去重；undefined 不表示完成。
- 记录暂停原因。只自动解除本次原生关注面板产生的暂停，保留普通切后台或玩家主动暂停；恢复应走已有安全恢复路径，释放输入，不能绕过待接续旧档的处理。
- 自动弹出的开局礼物也属于入口验收。正常 URL、新档、活动有效时间、短屏和旋转时，关闭/领取/略过无需自动滚动即可命中；内容区独立滚动，页头与操作区留在可视范围。用领取或取消后的实际出拳/移动证明返回成功。
- 比较旧 ZIP 失败与新 ZIP 通过，测一次真实按下完成业务操作；同时保留已关注零弹窗、取消关注回收、乱序回调、无生命周期事件返回、普通后台仍暂停以及存档重开的回归。
