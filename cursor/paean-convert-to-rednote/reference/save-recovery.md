# 小红书存档恢复、重试与上游合并保留

用于排查「重开丢档」「每次都存不住」、接入设备/云存档，或把新版上游合并进已有小红书作品。源于《铁拳越狱》2026-11-18 修复；平台契约与本例工程参数分开记录，不要求其他作品照搬字段、超时或快照数。

## 平台边界

以下为 2026-11-18 核对的[官方 Storage 文档](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s3-7)与[云存储文档](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s3-16)。后续实现前重新核对在线契约。

| 能力 | 约束及影响 |
| --- | --- |
| 设备 Storage | 客户端 9.46.0+；单 key 最大 1 MB，工具全部缓存最大 10 MB；`data` 为 JSON 字符串，读写 `encrypt` 一致 |
| 设备容量 | `getStorageInfo()` 返回 `keys`、`usedBytes`、`limitBytes`；以实际字节上限预检，不把 MB 擅自解释成更大的二进制上限 |
| 云存储 | 客户端 9.51+，仍为内测且需授权；1006 时隐藏云端入口，保留设备存档能力，不能作为唯一保存方式 |
| 云端大小 | 每条 `content` JSON 序列化后的 UTF-8 最多 65,536 字节；每批最多 100 项；不是字符数限制 |
| 云端读取 | 默认每页 20 条；遍历 `nextCursor`，末页不返回该字段。读取失败不是空列表，分页未完成不能视为无旧档 |
| 云端写入 | 批量非事务，逐项检查 SUCCESS / FAILED / UNKNOWN；`updateCloudStorage` 整行覆盖、无版本检查，迟到旧请求可能覆盖新进度 |
| 云端限频 | 默认每工具每接口 150 QPS；自动备份节流，不在帧循环调用；官方此页未承诺每用户总容量 |

禁止用 localStorage、sessionStorage、IndexedDB、Cookie 或 Cache API 代替容器存档。旧浏览器数据只能用于一次性迁移读取，属性 getter 也要放在异常保护内。版本未知、SDK / 方法缺失时显示能力暂不可用并允许重试；低版本提示升级。内存只维持当前会话，不得显示为「已保存在本机」。

## 读取与旧档恢复

- 分开记录「未读完 / 读取失败」「确认没有旧档」「有效旧档」；不要用 `catch => {}` 或 `null` 把失败伪装成新玩家。旧档未读清时，禁止默认新档写入该存储目标。
- 可以先显示可操作首页和 attract demo，临时进度暂存内存；UI 响应时间不等于存储完成时间。不要把 420–800 ms 的首屏等待时间当作旧档作废或创建新档的依据。
- 首次迁移核对已知历史 key、当前 key、缓存云档及其他有效备份。新 key 存在不代表进度完整，不能因此忽略旧 key。类型错误、坏 JSON、缺少分段不算有效档，仍应尝试其他完整副本；接口读取错误要保留原数据并重试。
- 合并前保留原副本；新格式完整写入并读回确认后，才记录迁移完成。后续优先使用已验证的新快照，避免每次启动重放旧奖励、旧钱包和旧道具。
- 后台恢复不得突然替换正在操控的世界。先保护恢复候选及新进度，在首页、暂停或其他明确安全时机应用；重新绑定关卡、背包、任务等持有的引用并释放输入，不能只修改 UI 上的关卡数字。
- 云查询返回空列表或失败都不应删除本机留存的已确认云档。恢复上限是仍存在的有效副本，不能承诺找回已经被全部清除或覆盖的数据；创作者不能直接读取其他用户的云存档。

## 写入、重试与容量

1. 将最新脏数据与在途请求分开；串行/合并写入，成功前不清 dirty 标记。读、写、读回校验都有有界等待，异常后释放队列；SDK 晚注入、前台返回、网络恢复及用户重试能继续工作。
2. 超时只结束等待，不取消宿主写入。使用不可变的版本化快照或等价的防旧请求覆盖机制；对同一快照的重试保持 key 和内容一致，不让同一 key 被拿去写更新内容。收到失败/丢失回执后仍可读回该 key，对上内容才确认成功。
3. 大档按最终 JSON 的 UTF-8 大小拆分，计入转义、元数据、分段列表的额外字节。先写并确认所有分段，最后提交主记录；恢复时只接受完整且属于同一快照的分段。分段解决单条上限，不会消除总容量上限。
4. 保留多份完整快照；清理仅针对本功能拥有的数据。容量紧张时仍保留至少一份已验证完整档；在此基础上可清理较旧快照和没有主记录的孤立分段，保护当前在途计划。不用 `clearStorage()` 腾空间，不先删除唯一旧档再尝试新写入。
5. 云端 UNKNOWN 先查询对账，复用已确认的同一份内容/分段，补齐缺失项，不盲目新增或改为覆盖旧行。玩家在重试期间继续游戏时，也要先完成原快照的对账，再处理更新数据；确认状态必须对应实际写成的那份内容。
6. 自动重试使用有上限的退避，保持按钮可操作并显示未保存状态。未授权不循环强开云入口；读失败、容量不足、部分写成、回执丢失不能统一提示保存成功。离页前尽量 flush，不能把一次异步 `pagehide` 当成保证落盘。

本例参数：设备调用 5 秒上限、失败后 2–30 秒退避、通常保留三份完整设备快照；云失败 5–60 秒退避，正常备份分钟级。首页最多等 400 ms 后显示，但后台旧档读取继续、完成前禁止设备写入。这些是工程选择，不是平台硬性时限。

## 合并进度不等于所有数字取最大值

最高分、已解锁收藏和永久能力可按业务规则取最大值/并集；钱包、消耗品、宠物口粮、装备槽、任务状态和当前挖掘应跟随胜出存档，不能复活已花掉的钱或已消耗道具。先比较重生/转生代数，再比较该游戏的长期进度；同进度时考虑保存时间，避免旧档「线索更多」把玩家主动重开后的新局覆盖掉。连续回收/取出道具需保留去重或消费记录。

关注权益采用最新已确认关系；取消关注不能被旧云档重新激活，一次性奖励和已消费余额不能重复发放。合并时同时保留前沿关卡、重访/支线状态、关卡种子与游戏生成版本，不能把两份档的关卡与运行中世界拼错。

## 合并上游时保留修复

以现有小红书适配版为工作基底，对照旧上游、当前适配版、新上游做差异合并。不要整目录覆盖 `src`，或拿新版上游的浏览器/Paean 存储替换本地适配层。

- 先读取项目的 `AGENTS.md`、存档说明、旧 key 清单和验收脚本，保存当前源码与 ZIP 基线。
- 保留设备/云适配层、启动读写隔离、安全恢复时机、失败提示/重试、快照及分段协议、旧档迁移和经济/关注合并语义；实现可以重构，行为与兼容性不能丢失。
- 上游新增 profile、run、收藏、装备、支线、重访或生成版本字段时，把它们接入加载、规范化、序列化和合并，不把旧完整档当成只含关卡数的简化档。
- 不随版本改存档 key、清空数据或删除旧字段。确需换格式时，增加可验证的一次性迁移；新档确认前保留旧副本。
- 同时保留该项目已修复的入口/触控、attract demo、关注核对/回收、排行榜自动提交/刷新与合理性过滤，避免存档修复随大文件合并被覆盖。
- 在合并后的最终 ZIP 上跑存档故障测试和正常全流程；记录 ZIP SHA-256，不能用上一个包的测试报告给新包背书。保留用户要求的交付范围，ZIP 交付不自动授权上传或送审。

## 最小回归矩阵

按实现覆盖以下可观察结果；故障注入、普通浏览器、旧 WebView、官方模拟器和真机结果分别说明。

| 场景 | 必须观察的结果 |
| --- | --- |
| 浏览器存储 getter 抛错，SDK 晚到/版本未知/低版本 | 入口可操作；能力提示真实；SDK 就绪后可重试；没有新浏览器持久化写入 |
| 原生读取慢、拒绝或不返回，期间开始新游戏 | 原副本未被覆盖；恢复后在安全时机接续，且输入不被锁死 |
| 新 key 第 1 关、旧 key 更高进度；只有缓存云档 | 找到更完整进度并持久化；三次重开不重复发奖、不退回已花金币 |
| 写入拒绝、永久挂起、回执丢失、迟到旧请求 | 队列不永久堵塞；自动/手动重试有效；读回确认；重开不会倒退到迟到旧写入 |
| 损坏新快照、部分分段、设备配额不足及孤立分段 | 回退完整档；不接受半份存档；保留最近完整备份，只清理自身可清理数据 |
| 云端第二页有旧档、翻页失败、UNKNOWN、重试时游戏继续 | 全页合并；读失败不写；固定原计划对账；完成状态与实际快照一致 |
| 中文/emoji/换行大档、设备 >1 MB、云端 >64 KiB | 每条实际 UTF-8 大小合规，分段往返内容一致；新设备/重开恢复成功 |
| 暂停/继续、主动重开、语言重载、重访/支线、取用道具、取消关注 | seed/进度/钱包与消费语义正确，界面和输入恢复；已有平台修复未回退 |

《铁拳越狱》案例在小红书工作区 `rednote-1107/brickfist-breakout/`：`SAVE-RECOVERY.md`、`scripts/verify-save-storage.mjs`（19 项故障用例）、`scripts/verify-save-zip.mjs`（9 项 ZIP 恢复用例）、`scripts/verify-minitool.mjs`、`qa/save-recovery-20261118/`。这些数量是本次证据，不是所有作品的固定指标。已有成就提示队列会延迟普通 Toast；测按钮反馈时隔离前序提示，不能把旧测试的 2 秒等待直接当作按钮失效，也不能为过测试删除游戏提示逻辑。
